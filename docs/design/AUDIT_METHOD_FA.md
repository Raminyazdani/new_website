# روش ممیزی و دامنهٔ شواهد

تاریخ ثبت: ۲ نوامبر ۲۰۲۶. این دفتر برای آماده‌سازی بازطراحی درخواستی و نگهداری چک‌لیست ساخته شده است؛ اجرای ممیزی مرورگری نیست.

## منابع و قرارداد

- چک‌لیست `02_Website_Audit_1000_Questions.md` با ۱۰۰۰ پرسش و ۵۰ حوزه به‌طور کامل خوانده و شناسه‌ها، متن سؤال‌ها و نگاشت حوزه‌ها از خود فایل استخراج شد. SHA-256 و نام منبع در `audit-results.json` ثبت شده است.
- `03_AI_Execution_Playbook.md` به‌طور کامل خوانده شد. اصل راهنما: کد یا screenshot محدود جای آزمون رفتاری نیست؛ وضعیت `NOT_TESTED` به معنی قبول نیست؛ هر N/A باید دلیل واقعی داشته باشد؛ یک شاهد باید scope و محدودیت روشن داشته باشد.
- در این مرحله هیچ پرسشی به PASS، FAIL، PARTIAL، N/A یا BLOCKED تغییر نکرده است. هر ۱۰۰۰ رکورد `NOT_TESTED` باقی مانده‌اند تا بازطراحی و آزمون‌های بعدی با شاهد واقعی سنجیده شوند.

## آنچه به‌صورت ایستا بررسی شد

فقط inventory و فایل‌های محصول لازم برای شناخت مرزها خوانده شد: `README.md`، `docs/PORTFOLIO_CONTRACT.md`، `docs/PORTFOLIO_PLAN_FA.md`، `package.json`، `public/index.html`، `public/lab.html`، `public/data/cv-adapter.js`، `public/data/portfolio-source.js`، `api/cv.js`، `api/session.js`، `server/auth.js` و `server/dev.js`. شناسهٔ هر منبع و هش snapshot آن در `source_index.json` است.

Routeهای هدف طبق scope هماهنگ‌کننده ثبت شده‌اند، اما با مرورگر تأیید نشده‌اند: `/` استودیوی سه‌مفهومی؛ `/lab.html` آرشیو حفظ‌شدهٔ ۲۰ طرح Hero؛ `/editions/bioteal/` نسخهٔ اصلی BioTeal؛ `/design-notes.html` فهرست عمومی طراحی بدون دادهٔ شخصی؛ `/api/cv` دریافت CV خصوصی؛ `/api/session` نشست POST/DELETE. وضعیت‌ها و منبع هر مورد در `audit-results.json` و `source_index.json` آمده‌اند. موارد صفحه‌ای در انتظار آزمون مرورگرند و APIها در این نوبت runtime-test نشده‌اند.

قرارداد حفظ‌شونده: دادهٔ CV فقط از source API و adapter عبور می‌کند؛ UI با `PortfolioModel v1` کار می‌کند؛ نشست خصوصی و کنترل مجوز سرور باقی می‌مانند؛ فایل CV، شناسه‌ها، secretها و محتوای خصوصی در خروجی عمومی قرار نمی‌گیرند. طراحی جدید باید سه مفهوم قابل‌تعویض را در رابط ارائه کند، اما داده و احراز هویت را از مفهوم بصری مستقل نگه دارد.


## دروازه‌های پذیرش متمرکز

چک‌لیست کامل برای ردیابی حفظ می‌شود؛ بازطراحی نباید ادعای اجرای هزار آزمون کند. اولویت اجرای نهایی ۲۲ شناسهٔ `priority_audit_ids` در ledger است. پذیرش سه مفهوم باید نشان دهد: هر مفهوم از نظر ترکیب/رنگ/عنصر بصری قابل تشخیص است؛ همان اطلاعات CV معتبر را از یک `PortfolioModel v1` نشان می‌دهد؛ تغییر مفهوم و تم محتوای اصلی را عوض نمی‌کند؛ سه تم روشن آبی، سفید و تیره روی متن، کنترل و فوکوس قابل استفاده‌اند؛ تصویرسازی زیستی/مولکولی/شیمی/کد تزئینی و غیرتجربی شناخته می‌شود؛ و کنترل انتخاب مفهوم/تم با کیبورد و عرض موبایل کار می‌کند. آزمون واقعی این معیارها هنوز انجام نشده و همهٔ ردیف‌های مرتبط `NOT_TESTED` هستند.

مرزهای غیرقابل تغییر طراحی: source-only data adapter؛ API خصوصی CV؛ احراز هویت و مجوز سمت سرور؛ عدم ارسال/ذخیرهٔ CV خصوصی در asset عمومی یا screenshot؛ و عدم ساختن واقعیت، پروژه، مدرک، KPI یا خروجی علمی. اطلاعات عمومی هر سه مفهوم باید فقط از همان مدل و از دادهٔ تأییدشده بیاید.

## آنچه آزموده نشد

هیچ مرورگری باز یا هدایت نشد؛ screenshot، DOM runtime، keyboard/touch، contrast، responsive، API request، cookie/session، شبکه، production، آزمون خودکار، تست‌ها، dependency یا Git بررسی/اجرا نشد. این متن هیچ ادعای PASS، سلامت بصری، انطباق WCAG، امنیت کامل، کیفیت انتشار یا پوشش دستگاه ندارد. یادداشت‌های قدیمی BUILD_PROGRESS و طرح‌ها به‌عنوان شاهد این ممیزی دوباره استفاده نشده‌اند.

## ادامهٔ کار

پس از پیاده‌سازی، شناسه‌های اولویت‌دار در ledger آزموده شوند: هدف/محتوا و دادهٔ عمومی؛ route و جداسازی عمومی/مدیریتی؛ تم و کنتراست؛ reflow و کنترل لمسی؛ keyboard و landmark؛ راست‌به‌چپ؛ پیوندهای اصلی؛ حفاظت secret و مجوز سرور؛ اعتبار پاسخ API، عدم‌تحویل داده به کاربر بدون مجوز، بازیابی نشست؛ صحت وضعیت رزومه؛ و تمایز تصویرسازی تزئینی از نتیجهٔ اندازه‌گیری. آزمون مرورگری باید route، state، viewport، ورودی، theme، روش، انتظار، مشاهده و مسیر شاهد را ثبت کند. آزمون‌های واقعیِ نیازمند دسترسی یا محیط اجرا تا زمان فراهم‌شدن همان محیط `NOT_TESTED` می‌مانند.
