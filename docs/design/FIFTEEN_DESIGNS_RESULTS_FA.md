## شواهد آزمون و مرورگر

طبق گزارش هماهنگ‌کننده، ۴۱ از ۴۱ آزمون تغییر‌یافته پاس شده‌اند؛ در این مرحله آزمون دوباره اجرا نشد. آزمون [design-registry.test.js](../../tests/design-registry.test.js) ثبت ۱۵ شناسهٔ یکتا، metadata و rendererهای لازم، تفاوت hero هر طراحی، یک h1، نگهداری هویت/عکس/متن منبع، escape ورودی ساختگی مخرب، و رد شناسه‌های تکراری یا طراحی ناقص را بررسی می‌کند.

فایل واقعی responsive شامل ۵ مجموعهٔ ۱۵تایی است: **۷۵ مشاهده برای ۱۵ طراحی** در viewportهای اسمی ۳۲۰، ۳۹۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل. عرض محتوای اندازه‌گیری‌شده به‌ترتیب ۳۰۵، ۳۷۵، ۷۵۳، ۱۰۰۹ و ۱۴۲۵ پیکسل بود. هر ۷۵ ردیف `scrollWidth` برابر عرض محتوای اندازه‌گیری‌شده داشت و overflow افقی نداشت؛ مقدار `nameOverflow` نیز در هر ۷۵ مورد صفر بود. مشاهدات تمام‌صفحهٔ ثبت‌شده ۱۱ بخش، یک h1 و ۸۷ رکورد پروژه را نشان می‌دهند؛ عکس واقعی با ابعاد گزارش‌شدهٔ ۷۲۰ پیکسل بارگذاری شده بود.

این داده‌ها اثبات نمی‌کنند که همهٔ تعاملات، حالت‌های تم، دسترس‌پذیری یا هر دستگاه/مرورگر به‌صورت زنده آزمایش شده‌اند. به‌ویژه فایل خام به‌تنهایی تعامل modal، جست‌وجو، README، مدارک و مهارت‌ها را برای هر ۱۵ طراحی ثابت نمی‌کند.

## تفاوت واقعی در ارائه

این مجموعه صرفاً پانزده رنگ یا تم نیست؛ هر طراحی ترکیب و ساختار متفاوتی دارد و بر همان مدل دادهٔ مشترک کار می‌کند:

| شناسه | زبان ارائه |
| --- | --- |
| `journal` | مقالهٔ پژوهشی با حاشیه‌نویسی، شکل شماره‌دار، فهرست ردیفی کار و ledger سابقه |
| `helix` | صحنهٔ علمی سینمایی با تصویرسازی DNA، پنل‌های روشن و timeline دو‌ریل |
| `organic` | ترکیب ارگانیک با ارائهٔ پروفایل و پروژه بر پایهٔ دادهٔ منبع |
| `monograph` | ساختار شبیه تک‌نگاری با تأکید تایپوگرافیک و بخش‌بندی مقاله‌ای |
| `specimen` | قاب صفحهٔ نمونهٔ آزمایشگاهی و نمایش دسته‌های منبع |
| `pipeline` | ترکیب فرایندمحور برای جریان کار و سابقه |
| `bento` | شبکهٔ ماژولار tileها برای گروه‌بندی هویت و رکوردها |
| `atlas-map` | اطلس شمارش و نمایهٔ دسته‌ها؛ نمودارها دسته‌بندی را نشان می‌دهند، نه مهارت اندازه‌گیری‌شده |
| `console` | بازرس رکورد با disclosure بومی، JSON واقعی هویت و قفسه‌های فشرده |
| `blueprint` | صفحهٔ نقشه‌کشی با هویت حاشیه‌نویسی‌شده، شماتیک شمارش و جدول‌های فنی |
| `chromatography` | laneهای رنگی منبع، لایه‌های شفاف و ریتم دفترچهٔ آزمایشگاه |
| `gallery` | جلدهای بزرگ و گالری افقی پوسترمانند برای پروژه‌ها |
| `dossier` | آرشیو نمایه‌شده با برگهٔ پروفایل و ledger پروژه |
| `kinetic` | تایپ بزرگ و پرتحرک، قاب پرتره و توالی پروژه با کنتراست زیاد |
| `horizon` | منظرهٔ علمی پانورامیک چندلایه و ارائهٔ متناوب پروژه‌ها |

شرح‌ها با registry و فایل‌های طراحی تطبیق داده شدند؛ طرح‌های اطلس و نمونهٔ آزمایشگاه دسته‌بندی/شمارش واقعی منبع را ارائه می‌کنند و ادعای اندازه‌گیری مهارت یا نتیجهٔ علمی نمی‌سازند.

## قابلیت‌های مشترک و مرز شواهد

طرح‌ها از مدل نرمال‌شدهٔ مشترک استفاده می‌کنند و rendererهای hero/about/projects/experience دارند. helper پروژه قابلیت جست‌وجو، فیلتر موضوع، دکمهٔ بازکردن جزئیات و حالت خالی را فراهم می‌کند. آزمون registry escape ورودی نامطمئن ساختگی را بررسی می‌کند. تم و پس‌زمینه در لایه‌های مشترک پورتفولیو/استودیو مدیریت می‌شوند.

تست registry صرفاً رندرشدن بخش‌ها را بررسی می‌کند؛ این مدرک به‌تنهایی عملکرد واقعی هر کنترل در browser و برای تک‌تک طرح‌ها را اثبات نمی‌کند. قابلیت‌هایی نظیر README، مدارک، مهارت‌ها، جست‌وجو و modal باید بر شواهد و تست‌های جداگانهٔ خود تکیه کنند. مدرک حاضر تغییر/انتشار در production را گزارش نمی‌کند.

خلاصهٔ ماشینی، فهرست شناسه‌ها، شمارش دقیق شواهد و محدودیت‌ها در [FIFTEEN_DESIGNS_RESULTS.json](./FIFTEEN_DESIGNS_RESULTS.json) آمده است.
