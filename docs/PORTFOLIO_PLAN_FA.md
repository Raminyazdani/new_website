# برنامهٔ ساخت پورتفولیوی کامل

هدف: تبدیل CV واقعی به یک وبسایت شخصی کامل، منسجم و چشمگیر برای پژوهش/دانشگاه و شرکت‌های فناوری؛ جزئیات بصری فراوان با معماری ساده. اطلاعات شخصی فقط از منبع داده می‌آید. فایل CV و رمزها وارد Git نمی‌شوند.

## فازها و پایان هر فاز

1. **قرارداد داده و لایهٔ تبدیل:** یک `PortfolioModel v1` ثابت تعریف شود. دریافت منبع و تبدیل ساختار خام فقط در `public/data/` باشد. هیچ Renderer بخش‌ها، کلیدهای خام JSON را نشناسد. نمونهٔ تغییر ساختار با آزمون مصنوعی نشان دهد که UI نیاز به تغییر ندارد.
2. **زبان بصری و ورودی:** زمینهٔ جوهری/سبز تیره، متن کرم، رنگ لیمویی با تاکید مرجانی؛ پرترهٔ واقعی، تایپوگرافی بزرگ، فضای چندلایه، ناوبری شناور، نشانگر پیشرفت، کنترل حرکت و جست‌وجوی مسیرها. Motion در حالت Auto به سیستم احترام بگذارد و Full فقط با انتخاب کاربر در همین سایت فعال شود.
3. **بدنهٔ اصلی:** Hero، معرفی، پروژه‌ها با جست‌وجو/فیلتر/نمایش بیشتر و جزئیات، تجربه‌ها با تایم‌لاین، پژوهش با وضعیت صحیح و citation. پروژه‌ها تصویر نتیجهٔ ساختگی یا امتیاز خیالی نداشته باشند؛ تصویرسازی‌های تزئینی از نتیجهٔ واقعی متمایز باشند.
4. **مسیر و ارتباط:** تحصیلات، تمام گروه‌های مهارت، گواهی‌ها و کارگاه‌ها، زبان‌ها و نمره‌های موجود، معرف‌ها با تماس پنهان، پروفایل‌ها و تماس واقعی. همهٔ رکوردها از طریق بازکردن/فیلتر/نمایش بیشتر در دسترس باشند.
5. **اتمام و تحویل:** آزمون نهایی Adapter، ورودی ناقص/نامطمئن، کامل‌بودن شمار رکوردها، تعامل‌های مهم، حفاظت API، نبود اطلاعات خصوصی در Git، و انتشار واقعی در همان مخزن و Vercel موجود. نتیجهٔ بصری مشاهده‌نشده موفق معرفی نشود.

## معماری کم‌حجم

`Source (fetch/file/other) → Adapter → PortfolioModel v1 → Renderers → Runtime interactions`

`public/data/cv-adapter.js` تنها مالک شکل فعلی CV است. `public/data/portfolio-source.js` تنها مالک transport و parsing منبع است. API فعلی Neon همچنان کل سند را بدون بازنویسی برمی‌گرداند. ذخیره‌ساز backend سند را opaque نگه می‌دارد و نباید schema نمایشی را اعتبارسنجی کند. برای منبع آینده، تنها این مرز و در صورت لزوم تنظیم اتصال آن تغییر می‌کند؛ Rendererها با قرارداد ثابت می‌مانند. بدون framework تازه، CMS، سرویس پرداختی جدید یا بازنویسی API.

نسخهٔ کامل در `/`، آزمایشگاه ۲۰ Hero در `/lab.html`؛ دسترسی خصوصی موجود حفظ می‌شود. داده یا رابطه، خروجی پژوهشی، proficiency یا نتیجهٔ پروژه اختراع نشود. تاریخ نامعتبر/ناقص به‌جای تصحیح حدسی، متن اصلی یا مقدار خالی بماند.

## وضعیت اجرا

فازهای ۱ تا ۴ پیاده‌سازی و یکپارچه شدند. در فاز ۵، آزمون‌های داده/تعامل و بررسی واقعی مرورگر دسکتاپ/موبایل انجام شده است؛ وضعیت انتشار نهایی در BUILD_PROGRESS.json ثبت می‌شود.
